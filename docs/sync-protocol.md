# 同步协议

当前迁移建立事项、目标和课程三类用户私有数据。客户端保留本地数据库作为主界面数据源，云端只负责跨设备同步与恢复。

## 上传

- 新记录由客户端生成 UUID，并以 `sync_version = 0` 插入；触发器固定账户归属并写入版本 1。
- 修改记录必须同时按 `id` 与本地已知的 `sync_version` 过滤。影响 0 行表示远端已经变化，客户端不得覆盖，必须先拉取并进入冲突处理。
- 删除是一次普通更新，只填写 `deleted_at`，不发送物理 DELETE。
- `user_id` 不能由客户端转移；触发器在更新时始终沿用旧值。

## 下载

客户端保存最后完整应用的全局 `sync_seq`。调用 RPC `pull_changes(p_after, p_limit)`，按顺序在一个本地事务中应用返回记录；事务成功后才保存最后一条游标。返回达到上限时继续分页，返回为空时结束。

RLS 会让函数内的三张表只返回当前登录用户的数据。全局序列可以在不同用户之间留空洞，客户端只要求游标递增，不要求连续。

## 冲突

同一记录的远端版本高于本地基线且本地也有未上传修改时，标记为冲突，不自动覆盖。无本地修改时直接采用远端；上传成功后采用服务端返回的版本和游标。软删除参与相同规则，防止另一设备把已删除记录恢复。
